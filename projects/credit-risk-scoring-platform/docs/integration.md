# Integration Guide and Adapter Boundaries

## 1. Repository Context (`Risk-ML`)

This project lives under `projects/credit-risk-scoring-platform/` inside the `Risk-ML` repository alongside sibling prototypes (`account-takeover-detection-engine`, `aml-transaction-monitoring-engine`, `chargeback-prediction-engine`, `graph-based-fraud-detection-engine`, `payment-authorization-optimization-engine`, `real-time-transaction-risk-platform`, `smart-payment-authentication-engine`).

Checked sibling paths at implementation time:
- `projects/account-takeover-detection-engine/` contains `pyproject.toml`, `requirements.txt`, and `config/default.yaml` (no shared Python library package yet).
- All other sibling directories currently contain `plan.md` specifications only.

Accordingly, `credit-risk-scoring-platform` is packaged as a clean, standalone Python library (`credit_risk`) with typed adapter interfaces and **zero imports from sibling directories or private/proprietary code**.

## 2. Library and Adapter Interfaces

| Interface | Module | Purpose |
|---|---|---|
| `validate_applicant_record` / `validate_label_record` | `credit_risk.contracts` | Point-in-time schema validation & leakage firewall for upstream data pipelines |
| `FeaturePipeline` | `credit_risk.features` | Versioned stateless/serializable feature transformation (`to_state_dict` / `from_state_dict`) |
| `BasePDModel` | `credit_risk.models` | Swappable model adapter supporting `LogisticRegressionPDModel` and `BoostedTreesPDModel` (`sklearn_hist_gb` or optional `xgboost`) |
| `PDCalibrator` | `credit_risk.calibration` | Post-hoc calibrator (`sigmoid` or `isotonic`) with monotonicity verification |
| `CreditRiskScorer` | `credit_risk.inference` | Typed scoring service (`score_applicant`, `score_batch`, `replay_decision`, `save_bundle`, `load_bundle`) |
| `ManualReviewStore` | `credit_risk.review` | JSON-backed review queue and audit log adapter; can be replaced by a database adapter in downstream systems |

## 3. Optional Dependency Adapters

1. **XGBoost (`models.boosted_trees.backend: "xgboost"`):**
   - Optional extra (`pip install -e ".[xgboost]"`).
   - If requested without `xgboost` installed, `BoostedTreesPDModel` raises `UnsupportedInputError` with installation instructions rather than falling back silently.
2. **SHAP (`explainability.use_shap_if_available: true`):**
   - Optional extra (`pip install -e ".[shap]"`).
   - When installed and enabled, `DecisionExplainer` uses `shap.TreeExplainer`; otherwise it uses deterministic `marginal_baseline_log_odds` and records the active method in `DecisionExplainer.explanation_method`.

## 5. Production Boundaries (Out of Scope)

Live credit bureau APIs, core banking loan-origination systems, automated underwriting approval engines, PII storage, and production authentication/TLS are **explicitly disabled and out of scope**. Any downstream production adaptation requires independent security, fair-lending legal, model-risk management (SR 11-7), and operational review.
