# Operator and Developer Runbook

## 1. Local Setup (Clean Checkout)

From `projects/smart-payment-authentication-engine/`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

## 2. Running Validation and Reproducible Demo

Run the complete test suite and two-pass reproducibility verification:

```bash
.venv/bin/python scripts/validate_all.py
```

Or run steps individually:

```bash
# 1. Automated test suite
.venv/bin/python -m pytest

# 2. End-to-end demo & report generation
.venv/bin/python scripts/run_demo.py
```

Outputs generated by `run_demo.py`:
- `artifacts/models/<model_version>.joblib` and `.manifest.json` (with SHA-256 checksum)
- `reports/baseline_vs_calibrated_metrics.json`
- `reports/policy_tradeoff_frontier.json`
- `reports/chronological_evaluation.json`
- `reports/step_up_simulation_summary.json`
- `reports/decision_log.jsonl`
- `reports/run_metadata.json`

## 3. Running the Local API Server

```bash
.venv/bin/python scripts/serve_api.py
```

Example requests:

```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
curl -s http://127.0.0.1:8000/v1/metrics | python3 -m json.tool
```

## 4. Diagnostics and Observability

- **Structured Decision Logs:** `AuthenticationEngine` emits JSON-structured logs (`policy_decision`, `model_scoring_failure`) containing `decision_id`, `payment_id`, `action`, `calibrated_fraud_prob`, `mandatory_rule_triggered`, `override_triggered`, `fallback_used`, `reason_codes`, `model_version`, and `policy_version`.
- **Diagnostic Counters (`/v1/metrics`):** Tracks `total_requests`, per-action counts, `mandatory_rule_hits`, `override_hits`, `fallback_hits`, `model_outage_hits`, `missing_feature_fallbacks`, `step_up_simulations`, and `replay_requests`.
- **Decision Replay (`/v1/replay/{decision_id}`):** Re-evaluates a stored event and returns `exact_match: true/false` comparing original vs. replayed decision fields.

## 5. Failure Modes and Recovery Procedures

| Failure Condition | Observed Symptom | Automated Behavior | Operator Recovery Step |
|---|---|---|---|
| **Missing or invalid config file** | `ConfigurationError` at startup | Process fails fast with exact file/field diagnostic (no silent fallback to unknown defaults). | Restore valid `config/default.yaml` and re-validate with `load_config`. |
| **Model artifact missing or tampered** | `ModelOutageError` / SHA-256 mismatch | Artifact loader rejects corrupted binary; if engine runs with `model_available=False`, deterministic fallback activates immediately. | Re-run `scripts/run_demo.py` to regenerate model artifact and verify manifest SHA-256. |
| **Runtime model scoring exception or NaN score** | `model_scoring_failure` warning log; `model_outage_hits` increments | Deterministic fallback executes (`fallback_used=True`) while preserving mandatory challenge rules and high-risk overrides. | Inspect model logs, toggle `set_model_outage(False)` once healthy artifact is loaded, and verify via `/health`. |
| **Missing critical features or telemetry drop** | `missing_feature_fallbacks` increments | Routes to deterministic fallback (`challenge`, `decline`, or `abstain` if `missing_feature_ratio >= 0.65`, never bypassing mandatory rules). | Investigate upstream device SDK / feature store pipeline; replay affected `decision_id`s once telemetry is backfilled. |
| **Out-of-order event stream in batch eval** | `ChronologicalOrderError` | Evaluation aborts loudly rather than silently leaking future ordering. | Sort batch input strictly by UTC `timestamp` and re-run. |
| **Process restart** | In-memory counters reset | When `JsonlDecisionStore` is configured, persisted decisions reload cleanly from `decision_log.jsonl` on startup for audit and replay. | Point `storage.jsonl_path` to persistent volume; verify replay on recent `decision_id`s. |

## 6. Known Limitations

- Synthetic data distribution and simulated step-up outcomes are educational approximations, not calibrated to real issuer/merchant portfolios.
- Not an EMVCo 3DS 2.x or PSD2 SCA compliance implementation.
- Live Redis persistence is optional and untested against an external Redis daemon in this offline environment.
